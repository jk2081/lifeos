## M1 Spaces and permissions

- Works: `Life Space` with members and Read or Write access, roles `Life Admin`, `Life User`, `Life Agent`, `permission_query_conditions` and `has_permission` hooks on every DocType with a `space`, the same checks for `Life Space` itself, helper checks used by API methods. Agents cannot delete, cannot change spaces or settings.
- Tests: `lifeos/tests/test_m1_permissions.py` passes, with an owner, a family member who is only in the shared space, and an agent.
- Not yet covered here: file access and search for a second user (tested in M3 and M8), `review.decide` refusal for agents (M3).

## M2 Data model

- Works: all DocTypes of sections 4, 4a and 4b (32, generated by `scripts/gen_doctypes.py`), the organisation fields and their rules (area and tags from the record's own space, project inside `area` or `also_in`), the shared `Life Index` handler on save, archive and delete, `bench execute lifeos.index.rebuild`, composite and FULLTEXT indexes, validations (last four characters only in the vault, check-in ranges, habit log uniqueness, waiting reason, cycle end date), `[[link]]` parsing into `Life Link`, the `life_space` custom field on `Event`, seed and unseed (`lifeos.seed.load`, `lifeos.seed.remove`). Install creates the `Private` and `Shared` spaces with their areas and check-in dimensions.
- Tests: `lifeos/tests/test_m2_data_model.py` passes.

## M3 Inbox and review

- Works: `inbox.create_item`, `claim_next` (oldest first, 30 minute claim timeout, returns file URLs and the filing context), `submit_result` (field-by-field payload validation, invalid proposals refused and the rest kept, one new tag per item), `fail_item`, `retry`, `review.decide`, `review.decide_all`, `review.update_payload`, `meta.proposal_schema`. Every proposal kind creates its record and links it back to the inbox item. Agents are refused on every decision path. Files are private, originals are never changed, images get one preview of at most 1600 px.
- Screens: Inbox (drop zone, instruction box, lists by status, Retry) and Review (original, transcript with edit, summary, proposals with one-tap area, project, also-in, tag and due-date chips, Edit dialog, Accept all, Reject all). Checked at 1440 px and 390 px against `mockups/02-review-desktop.png`.
- `agent/fake_agent.py` runs the pipeline over HTTP with an API key, with canned results.
- Tests: `lifeos/tests/test_m3_inbox.py` passes (23 tests).
- Untested against a real service: a real agent over MCP. The fake agent uses the same methods over REST.

## How to run the local stack

```
docker compose -f docker/docker-compose.yml up -d
docker exec -d lifeos-bench bash -lc 'cd ~/frappe-bench && bench serve --port 8000'
cd frontend && npx vite build        # rebuild the front end
docker exec lifeos-bench bash -lc 'cd ~/frappe-bench && bench --site lifeos.localhost run-tests --app lifeos'
```
